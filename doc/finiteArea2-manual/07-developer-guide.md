## 7.1 Building

`libfiniteArea` depends only on `libfiniteVolume` (and its dependencies):

```bash
# shared-core changes (if touched)
wmake libso src/OpenFOAM
wmake libso src/finiteVolume
# the library
wmake libso src/finiteArea
# a solver
wmake applications/solvers/finiteArea/liquidFilmFoam
```

Because area/edge fields, matrices and schemes are templated and instantiated in
`libfiniteVolume`/`libfiniteArea`, a solver that only *uses* them picks up
changes to those `.so`s at runtime (dynamic link) — but relink the solver after a
library change to be safe.

## 7.2 Test & validation applications

Under [`applications/test`](../../applications/test):

| App | What it checks |
|-----|----------------|
| `faMesh-try` | `faMesh` construction and selector behaviour. |
| `faMeshesRegistry` | FA mesh registry construction and lookup. |
| `faGeomCompare2`, `faGeomDump2`, `faRedist2` | Current-worktree focused geometry and redistribution checks when built. |
| `tutorials/finiteArea/Alltest` | Serial and parallel solver completion and field-regression gates. |

Additional scratch drivers may be kept outside version control; treat the
tutorial drivers and the source-level tests above as the reproducible entry
points.

Build the focused test applications with their local `Make` files, then run
`tutorials/finiteArea/Alltest` for the supported end-to-end cases.

### Comparing against historical FA results

Historical parity drivers can still be useful when checking geometry or
discretisation changes, but they must be run as separate reference cases. The
current tree has one FA library, `libfiniteArea`; do not build a test that links
both the earlier and current implementations.

### Parallel E2E

```bash
cd tutorials/finiteArea/liquidFilmFoam/cylinder
decomposePar -force && decomposePar -region film -force
mpirun -np 4 liquidFilmFoam -parallel
reconstructPar -region film -latestTime
# then diff <case>/<time>/film vs the serial baseline
```
(`system/film/fvSchemes`/`fvSolution` are only needed for `reconstructPar
-region film`, not for the solve.)

### Running the tutorial parity / CI harness

The migrated FA tutorials live under [`tutorials/finiteArea`](../../tutorials/finiteArea)
and are gated by a single driver:

```bash
tutorials/finiteArea/Alltest      # serial + parallel legs, prints PASS/FAIL tables
tutorials/finiteArea/Alltest --serial-only   # serial gates only
tutorials/finiteArea/Alltest-parallel        # just the MPI leg (also standalone)
```

`Alltest` is the single CI entry point: it runs the serial gates and then hands
off to the sibling `Alltest-parallel` (MPI) driver, exiting nonzero if **either**
leg fails. For every case it (1) runs `Allrun` to completion (hard gate: exit 0,
solver `End`, no `FOAM FATAL`), (2) diffs a key output field against a stored
reference within an explicit tolerance via
[`tutorials/finiteArea/test/faFieldDiff.py`](../../tutorials/finiteArea/test/faFieldDiff.py)
(index-wise `Linf`/`relL2`), and (3) applies any physical-invariant gate. The
references and tolerances:

| Case | Field | Reference | Tolerance | Observed |
|------|-------|-----------|-----------|----------|
| `surfactantFoam/planeTransport` | `Cs` @ endTime | **legacy** `surfactantFoam` (identical `blockMesh`+`faMeshDefinition`; `makeFaMesh`/`makeFaMesh` emit identical `faceLabels`) | `relL2 ≤ 1e-6`, `absTol 1e-8` | `Linf = 0` (bit-identical, flat manifold) |
| `sphereSurfactantFoam/sphereTransport` | `Cs` @ endTime | **legacy** `sphereSurfactantFoam` (identical shipped polyMesh) | `relL2 ≤ 5e-3` + `sum(Cs·V)` drift `≤ 1e-6` | `relL2 = 2.1e-3`, mass drift `0` |
| `liquidFilmFoam/cylinder` | `h` @ endTime | **self-regression** (see below) | `relL2 ≤ 1e-6` | `Linf = 0` |

Why the sphere tolerance is looser: on a **curved** manifold the reduced-order
`deltaCoeffs` uses the flat 3D chord where legacy FA uses the geodesic PN
distance; the two differ by `O(curvature·h)` (the documented-benign finding from
the historical parity study). The transport solution therefore differs by a small,
**time-stationary** amount (≈0.2 %, already present at the first write and not
growing) — a convention difference, not an error. The flat plane case has no
curvature and is bit-identical.

Why the film reference is self-regression, not legacy: `liquidFilmFoam` is
film-region-only (it builds the FA mesh on a `collapse2DMesh` `film` `fvMesh`,
not a standalone `makeFaMesh` region), so a like-for-like legacy field diff is
not structurally meaningful. The film case is covered by the serial and
parallel tutorial gates; the harness adds a
regression guard on `h`. References are regenerated by running the legacy solver
on a scratch copy of the case (surfactant/sphere) or the current finite-area
solver itself (film) and copying the final field into `<case>/validation/`.

### The parallel (MPI) leg

`Alltest-parallel` adds a PARALLEL gate on top of the serial one: it decomposes
each case, runs the finite-area solver under `mpirun` on a modest rank count, then
`reconstructPar`s and diffs the reconstructed field against the **serial**
`validation/<field>` reference. Parallel tolerances are **looser** than the
serial ones because a decomposed run differs from serial by linear-solver
ordering (a benign non-determinism that accumulates over the run) — the gate
certifies serial-equivalence to ordering tolerance, not bit-identity. The plane
leg runs the ensight `areaWrite` FO in parallel; the film/sphere legs keep
`-noFunctionObjects` only because they ship no FA function object.

| Case | np | field | par tol (relL2) | observed | result |
|------|----|-------|-----------------|----------|--------|
| `surfactantFoam/planeTransport` | 4 | `Cs` | `1e-4` | `relL2=7.3e-6` | PASS |
| `liquidFilmFoam/cylinder` | 4 | `h` | `3e-3` | `relL2=6.4e-4` | PASS |
| `sphereSurfactantFoam/sphereTransport` | 8 | `Cs` | `1e-4` | `relL2=7.1e-6` (+ mass `relDrift=8e-6`) | PASS |

Pipelines: the **standalone** FA region (plane) needs `makeFaMesh` **twice** —
serial (for the reference-comparable ordering) and `-parallel` (to persist the
per-rank reduced-order FA mesh the solver reads) — around a finite-area-aware
`decomposePar` that splits the FA *fields*:

```bash
blockMesh && makeFaMesh && decomposePar -force \
  && mpirun -np 4 makeFaMesh -parallel \
  && mpirun -np 4 surfactantFoam -parallel -noFunctionObjects \
  && reconstructPar -latestTime
```

The **film** region builds its FA mesh inside the solver from the
`collapse2DMesh` region (no `makeFaMesh`); decompose the base and the film
region (the latter reuses the top-level `decomposeParDict`):

```bash
blockMesh && collapse2DMesh film && setFields -region film \
  && decomposePar -force \
  && decomposePar -region film -force -decomposeParDict system/decomposeParDict \
  && mpirun -np 4 liquidFilmFoam -parallel -noFunctionObjects \
  && reconstructPar -region film -latestTime
```

The **sphere** case (closed `outer` sphere patch, np=8) runs the same standalone
pipeline as the plane (`makeFaMesh` → `decomposePar -force` → `makeFaMesh
-parallel` → solver → `reconstructPar`). It exercises two closed-manifold
parallel fixes: (a) symmetric per-neighbour processor-patch **construction**
(`faMesh::buildRegionMeshFromDefinition`: neighbour-identity `patchMap` +
`makeMesh(syncParallel=false)`, so the degenerate 2-point-face
`processorPolyPatch::order` reorder is skipped) and (b) parallel-consistent
**point-area-normal coupling** — `calcPointAreaNormals` sums point normals
through the *parent* mesh's global point coupling via the
`pointAreaNormalsParentMap` registry seam (see
[§4.2](04-geometry-and-schemes.md#parallel-point-area-normals-curvedclosed-manifolds)
and [§5.5](05-parallel-io.md)), without which `fac::grad` (hence the corrected
Laplacian) is decomposition-dependent at multiply-shared poles. It builds, runs
to completion on 8 ranks, conserves mass, and matches serial at `relL2≈7e-6`.
See also the coupled-patch trap under [§7.3](#-a-new-fa-discretisation-scheme)
and [§7.4](#74-debugging-tips--gotchas): the implicit `fam::laplacian` coupled-patch
matrix-coefficient path was the concrete parallel defect fixed to bring the
surfactant solvers online in parallel.

## 7.3 How to add …

### … a new FA discretisation scheme

1. Add the scheme under
   `src/finiteArea/finiteArea/<kind>Schemes/<name>/` following an existing one
   (e.g. `gaussFaLaplacianScheme`).
2. Reuse FV assembly (`fvMesh` accessors, `surfaceInterpolation` weights,
   `deltaCoeffs`); add only the tangential projection / transform that is
   genuinely FA-specific.
3. **Coupled patches**: never call the no-arg `snGrad()` on a boundary patch that
   may be coupled — guard `pvf.coupled()` and use the `deltaCoeffs` form
   (see [§4.4](04-geometry-and-schemes.md#44-surface-normal-gradient-lngrad-and-coupled-patches)).
   This is the single most common parallel-correctness trap.
4. Add it to `Make/files`, rebuild, and cover it with an MMS or parity case
   before relying on it.

### … an FA-specific boundary condition

1. Derive from `fvPatchField`/`fvsPatchField` (not a legacy `faPatchField`).
2. Prefer type-generic `evaluate()`/`updateCoeffs()` (as the generalised
   `clampedPlate` now is) so one template serves scalar/vector/tensor.
3. Enable it in `src/finiteArea/Make/files` and add a case that exercises it.

### … coverage to CI

Add a new tutorial to [`tutorials/finiteArea/Alltest`](../../tutorials/finiteArea/Alltest)
as a `completionGate` (always) plus a `fieldGate` against a stored
`<case>/validation/<field>` reference with an explicit tolerance (generate the
reference from the legacy solver where a like-for-like case exists, otherwise as
a self-regression baseline). For library-level coverage wire the relevant
`Test-*` app into a focused comparison driver the same way. Both loops are the current tutorial regression
gates; see [roadmap](08-roadmap.md).

## 7.4 Debugging tips & gotchas

- **Schemes not found on a generated mesh.** The pure NO_READ generation ctor
  does not read `fvSchemes`. Use the generate → `write()` → reload pattern
  (as `createFaMesh.H` and the tests do) so schemes are populated.
- **`coupledFvPatchField::snGrad() Not implemented` in parallel.** A scheme is
  calling the no-arg `snGrad()` on a processor patch — apply the coupled-patch
  guard (§4.4).
- **`coupledFvPatchField::gradientInternalCoeffs() Not implemented` in
  parallel.** The *implicit* analogue: an `fam::` matrix assembly is calling the
  no-arg `gradientInternalCoeffs()`/`gradientBoundaryCoeffs()` on a processor
  patch. Guard `psf.coupled()` and pass the patch `deltaCoeffs`
  (`gradientInternalCoeffs(pDeltaCoeffs)`), mirroring `fv::gaussLaplacianScheme`
  — see `gaussFaLaplacianScheme::famLaplacian`.
- **Parallel FA solver segfaults in `processorPolyPatch::order` /
  `reorderCoupledFaces` during construction.** Closed reduced-order regions now
  construct processor patches symmetrically and skip the degenerate polygon-face
  reorder. Recheck this path when changing `buildRegionMeshFromDefinition`.
- **Dimension mismatch (`[0 3 -2]` vs `[0 2 -2]`).** An implicit term declared
  its matrix dimensions from `dimVol` instead of `mesh().V().dimensions()`; on the
  reduced-order mesh `V` is `dimArea`.
- **Deadlock during construction/redistribution with an empty subdomain.** A
  collective (`nTopologicalD()`'s reduce, or a geometry collective) fired
  non-uniformly across ranks — ensure it is seeded uniformly (see
  `finaliseParallelBoundary`).
- **Edge (flux) field wrong sign after reconstruct.** The surface field is not
  `oriented`; set `oriented 1`.
- **Stale tangential transform after mesh motion.** Ensure the cache is cleared
  in `clearGeomNotOldVol` (already done for `edgeTransformTensorsPtr_`).
